# SQL vs NoSQL


**SQL (Relational Databases):**  
Structured databases that store data in tables (rows & columns).

**NoSQL (Non-Relational Databases):**  
Flexible, schema-less databases that store data as documents, key-value pairs, graphs, or wide-columns.


| Feature | SQL | NoSQL |
|--------|------|--------|
| Data Model | Relational (tables with rows & columns) | Non-relational (document, key-value, graph, wide-column) |
| Schema/Flexibility | Fixed, predefined | Dynamic, schema-less |
| Scalability | Vertical (adding more resources to single server) | Horizontal (adding more servers) & Distributing load |
| Query Language | SQL | No standard; database-specific |
| Relationships | Strong, normalized | Weak or through embedded documents |
| Transactions | ACID compliant | BASE (eventual consistency) |
| Best For | Structured data, complex queries | Big data, real-time, fast-changing data |
| Examples | MySQL, PostgreSQL, Oracle | MongoDB, Cassandra, Redis |
